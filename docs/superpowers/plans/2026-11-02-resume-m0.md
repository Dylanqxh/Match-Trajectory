# M0 简历工作台执行方案

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 在当前项目交付能实际启动、编辑、保存、确认并导出中文简历的 M0，同时准备可真实运行的模型连接和打包探针。

**Architecture:** React 工作台与 FastAPI 同源部署；SQLite 保存简历修订，导出绑定确认版本。模型连接与文档链独立验证；M0 不伪装成完整 Agent，不生成虚构个人事实。

**Tech Stack:** 现有 React／TypeScript／Vite、Python 3.12、FastAPI／Pydantic、SQLAlchemy／SQLite、python-docx、Playwright Chromium；PyInstaller 为打包探针依赖。

**Spec:** [产品](../../互联网求职简历Agent产品设计方案.md)、[Skill](../../简历Skill设计方案.md)、[Agent](../../简历Agent架构设计方案.md)。

## Global Constraints

- 在当前目录实施，保留现有文档和环境；不推送、不部署公网，不更改系统运行时。
- 五方向是后续专项验证目标；M0 演示人物必须标明虚构，手工内容不宣称经过 AI 审阅。
- 原材料每任务最多 20,000 字；本轮先实现文本输入，文件导入、完整 Agent 和真实试用归入后续阶段。
- 本地会话、Origin／Host 检查、版本冲突、确认失效必须随第一批接口交付。
- 真实供应商没有凭据时只验证适配器协议，记录未验证；不读取其他项目的 Key，不把模拟服务当真实接入。
- 不依赖 Office 导出 DOCX；PDF 使用本地 Chromium 与中文字体；产物和数据不进入 Git。

## Review Focus

- 用户另开标签页编辑：旧版本保存或确认返回冲突，不覆盖内容（任务 1、2）。
- 输入 HTML、脚本、恶意 URL：预览和导出转义，渲染不访问外部资源（任务 3）。
- 生成文件过程中正文变化：不能把旧确认当作当前有效导出（任务 3）。
- Key 错误、重定向或服务端回显敏感信息：不泄露 Key，失败保留旧设置（任务 4）。
- 没有开发环境的冻结程序：前端、字体和浏览器资源定位可重复，退出后无残留工具（任务 5）。
