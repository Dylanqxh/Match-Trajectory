# M1 AI 简历生成执行方案

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. 按任务执行，每项先观察测试失败，再实现并验证。

**Goal:** 用户配置模型、填写方向和少量材料后，得到有来源、可编辑、可核对导出的 AI 简历。

**Architecture:** 保留 React／FastAPI／SQLite；单执行器依次进行选材、起草、独立审阅与有限修正。任务持久保存，模型没有文件、命令或数据库权限。结果另存候选，采用时创建新简历。

**Tech Stack:** 现有 Python 3.12、Pydantic、SQLAlchemy、httpx、React、TypeScript、Playwright；不增加 Agent 框架依赖。

**Spec:** 现有产品、Skill 和 Agent 三份设计；本文件记录 M1 的实施边界，不替代长期方案。

## 本轮取舍

- 继续当前项目，单独开发分支；用户已全权授权，不重复询问设计和逐项确认。
- 在“一次提示词生成”“受控分阶段执行”“多 Agent 自由协作”中，采用第二种：便于核对、暂停、限额与重试。
- 首版继续粘贴文字。原文按段保存不可变证据 ID；不先让模型改写事实再自证正确。
- 通用 Skill 加后端、算法、分析、产品、运营五类规则；其他方向使用明确标注的通用规则。画像不是实时招聘 JD。
- 姓名、联系方式留在本地回填；用户主动粘贴在正文中的隐私仍会随材料发送，界面提交前说明。
- PDF／DOCX 导出沿用现有实现；上传解析、资料库、备份恢复和公开发布仍属后续阶段。

## Global Constraints

- 材料上限 20,000 字；可选 JD 上限 8,000 字。目标不是个人事实。
- 首次最多一轮三个问题，允许跳过；零材料直接返回框架与补充提示，不调用模型编经历。
- 整个任务最多八次模型请求、最多两轮修正；结构错误最多重试一次；单请求 45 秒，总执行 180 秒，等待用户不计时。
- 原文、JD、模型输出均为不可信数据；不能授权工具、改变规则或跳过检查。
- 独立审阅不读取起草者的自评。引用有效不等于语义真实，程序检查与模型审阅分别保留结果。
- AI 正式导出须当前版本有效审阅通过且用户确认；手工修改使审阅失效。允许明确的自行核对接管，但不能直接抹去已知阻断。
- Key 只在会话内保存；任务只存配置版本和非敏感描述。缺凭据或重启后由用户明确继续，不自动重放付费请求。
- 全部业务测试用隔离目录；不读取用户 Key，不把本地模拟服务当真实供应商验证。

## Review Focus

- 材料里有提示词攻击、否定限制或团队成果：保留原文边界，不能把 JD 写成个人能力。
- 页面刷新、重复提交、取消后迟到响应：不重复创建任务或采用结果，不恢复已取消任务。
- 等待补充期间或模型请求期间更换配置：原任务不偷偷改用新地址／模型。
- AI 稿手工修改、审阅失败或有阻断：普通确认不能绕过正式导出限制。
- 模型截断、空白 JSON、限流、重启与修正耗尽：保留已有材料与候选，预算不清零。
