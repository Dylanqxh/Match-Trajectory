# 简历信息结构与可读性改进执行方案

> For agentic workers: use executing-plans，在当前项目内按任务执行；不覆盖用户简历，不上传用户材料。

**Goal:** 从长段材料改写，改为具备固定教育信息、经历时间、清晰贡献和少量重点标记的简历交付。

**Architecture:** 保留主 Agent 与独立审阅；扩展现有内容结构。教育信息由用户固定输入，缺失时允许模型仅从原文抽取；明确填写的教育信息由程序回填，不由模型重写。经历增加类别、名称、组织、角色、起止日期。无日期保留未知；同类经历倒序。加粗使用正文中已有的短语，预览与两种文件共用内容，不解释任意 HTML。

**Tech Stack:** 沿用 Python／FastAPI、React、SQLite、HTML PDF 与 DOCX，不引入新框架。

**Spec:** 本轮用户的原始材料、截图及反馈；原产品、Agent、Skill 方案的事实可靠与可读性标准继续适用。

## 约束和验收

- 姓名、联系方式、目标岗位在首次生成前明确填写；联系方式接受手机号或邮箱，不限国家格式。无材料的框架体验和手工路径保留。
- 教育字段不改写、不推断学校或时间；仍可生成缺项草稿，缺项在工作台可见。
- 同类经历按结束时间倒序，在读／至今靠前；未知时间不伪装成已知时间，同时间保持原顺序。
- 标记仅能引用现有正文，不引入文字；修改正文后过期标记清除。元数据也进入来源检查、审阅、内容哈希和导出内容核验。
- 长段落、过多条目、冗长简介为质量提醒；生成可有限修正，不能把表达建议当事实阻断，不能在重审中漏掉任何编辑字段。
- 原输入、旧简历、旧任务仍可读取；不把本轮样本和个人信息写入公开测试。
- 不承诺“80%”已达成。规则、浏览器、排版验证与真实模型写作评测分别报告。

## 决策与验证记录

- 根因：内容只支持通用标题与段落，无法稳定表达教育、经历时间、个人角色与少量重点；Skill 有原则但缺选材和压缩预算，程序也没有质量反馈。
- 取舍：保留现有数据表，扩展 JSON；旧版默认字段不改变原内容哈希，旧版已接受的 section／item 标识仍可读取。新教育标识不能与现有内容混用。
- 质量规则为建议，不冒充事实问题。超长、重复、条目过多可在原预算内触发修正；缺时间只提醒。生成事实仍受独立审阅与程序检查约束。
- Agent／RAG 定向加载算法规则；“大模型产品经理”按产品规则处理，不因技术词误路由。原始目标仍保留，不将目标技能写成已有经历。
- 124 项自动测试、TypeScript、Vite、Ruff 通过。曾复现：教育审阅定位失败、长文未触发修正、拼接日期、岗位误路由、旧哈希失效和重复标题。
- 独立静态审阅发现三项重要问题：教育 ID 不在审阅定位范围、仅教育输入时无未保存保护、旧 ID 规则升级破坏读取；均已修复并补回归。教育未保存保护在真实浏览器先失败后通过。
- 源码浏览器与原手工路径通过，脚本错误0；覆盖固定教育、倒序、PDF／DOCX 重点、逐项人工核对、刷新及导出。证据位于 `artifacts/readability-source-final/`、`artifacts/readability-legacy-final/`，使用本地确定性 HTTP 模型，不证明真实模型写作质量。
- 重新构建便携程序并重复浏览器闭环通过：`artifacts/readability-frozen-final/`；本机服务更新前确认无在途任务并完成 SQLite 一致性备份，健康检查正常。Key 不迁移，后续 AI 生成须重新连接。
- 按本轮材料另做人工目标效果参考并检查一页版面，位于忽略目录 `artifacts/readability-reference/`；不是模型实际输出，未知学校、姓名和日期没有补造，不提交到仓库。
- 真实模型仍需对同一输入及不同方向做前后对照；不能用规则测试或人工参考宣称已达到70%—80%可用。
