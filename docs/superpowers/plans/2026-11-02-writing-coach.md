# 写作教练 Skill 与双维审阅执行方案

> For agentic workers: use executing-plans，在现有开发分支执行，不创建新工作区、不发布。Skill 方法先基线验证，代码变更先失败回归，再实现。

**Goal:** 把适配、贡献、亮点与易读转为模型可执行的方法，写作质量独立于事实结论，并实际驱动有限修正。

**Architecture:** 保留主 Agent、独立上下文审阅和固定预算。入口聚焦正向方法；宿主按岗位、用户明确选择的求职阶段和执行阶段加载参考与示例，冻结资源清单及版本。审阅一次请求同时产生两组独立结果，不增加每轮模型请求。

**Tech Stack:** 沿用 Pydantic、SQLite JSON、React，无新依赖。

**Spec:** 本轮用户给出的六项 Skill 诊断与落地建议；原产品的少量交互、事实可靠与当前版本确认仍适用。

## 决策

- 当前已有 editorial、岗位选择和长度反馈；问题是方法深度和审阅指标，不能把现状写成“全部缺失”。
- 新增 contract、evidence/common、questions、candidates 和正反例；入口写清路由，实际由宿主完成，模型不访问文件系统。
- 求职阶段可选校招／社招／转岗，未知用通用；空窗是可叠加标记，不从日期或学历擅自推断，不追问私人原因。
- 写作质量按适配、个人贡献、亮点证据、易读四维 0/1/2/不适用，须有理由和可定位证据；与事实通过分开，不能转换为80%或面试通过率。
- 有证据但遗漏或写不清，触发有限修正；输入确实缺证据，给出缺口，不反复扩写或扣成能力差。用户跳过后不再追问。
- 面试讨论点只基于当前段落，出现在辅助报告，不写进投递正文，不创建新面试模块。
- 旧报告可读，缺少质量结果显示未评估；旧 verdict=pass 不升级为写作质量通过。新协议要求双维结果，错误重试和总预算仍受限。

## 实际验证

- 自动回归138项通过，TypeScript、Vite、Ruff通过；保留一条Starlette／httpx上游弃用提示。
- 写作质量可在事实通过、正文不长时独立要求修正；缺材料不触发无限修正；错误正文／证据引用拒绝并计入原预算。修改后旧质量立即失效，旧报告不会自动出现质量高分。
- 审阅格式不注入预先填好的分数或结论；Schema负责结构，规则负责判断，教学例只教写法。
- 独立静态审阅发现未保存修改仍显示旧质量结论，已在浏览器先复现再修复；提示与预览绑定当前版本。
- 源码、手工兼容路径、重建便携程序均通过浏览器闭环，脚本错误0。覆盖质量报告失效、转岗＋空窗路由、固定教育、时间、重点、人工核对和PDF／DOCX。一次验收脚本因采用请求尚未返回就读取ID失败，补齐编辑器等待后通过，不作为产品缺陷。
- 证据：`artifacts/coach-source-final-2/`、`artifacts/coach-legacy-final/`、`artifacts/coach-frozen-final/`、`artifacts/coach-build.log`。这些流程使用本地HTTP测试模型。
- 指令探索：五个虚构留出场景，每场景各一次无规则与有规则的全新上下文测试，覆盖后端、运营转岗、产品、Agent与数据。两组均未观察到明显虚构，有规则组出现相关经历优先和追问取舍；不足以证明稳定增益或方差下降。教学例未包含这些留出案例，试验输出不进入产品提示词。记录在 `artifacts/coach-probes/report.json`。
