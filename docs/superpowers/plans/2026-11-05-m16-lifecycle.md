# M1.6 人工交付与记录管理执行计划

用户授权在当前功能分支直接迭代。目标：人工核对可完成接管和导出；用户可删除任务、简历和关联导出，不复活已删数据。

## 设计与接口

- 接管先保存编辑，有阻断进入明确的核对流程；逐项处理后直接继续确认接管。保留原审阅与依据，不能点击按钮清空事实阻断。补齐修改正文、移除问题条目、导出草稿入口。
- `DELETE /api/generation-jobs/{id}`：取消并隐藏任务，删除检查点；被已采用简历引用时保留必要来源，接口告知，直到删除对应简历再清除。未引用任务清除材料，保留无个人信息的取消标记以拒绝迟到写回。
- `DELETE /api/resumes/{id}`，JSON `expected_revision`：版本冲突返回409；删除正文、历史、AI标注、关联生成/重审任务与导出。不影响其他简历。
- 导出及删除共用执行锁；任务删除先撤销令牌再清理。检查点/导出文件清理建立可恢复的待办，失败不伪报完成；仅清理经过验证的任务ID、清单归属和工作区路径。
- 工作台中明确删除确认、剩余引用说明、取消/执行中任务的行为；删除后清理当前选择、缓存与弹窗。

## 执行与验证

1. 测试先行实现删除服务及API：鉴权、幂等、版本、关联来源、导出、检查点、迟到与重复请求。
2. 修复人工核对和接管前后端，源码浏览器实测“核对→接管→正式导出”，保留不允许绕过事实的测试。
3. 实现UI删除入口，浏览器验证独立/已采用/执行中任务及简历删除、刷新后不再出现。
4. 完整pytest、Ruff、TypeScript、Vite、原M1/M1.5回归、新生命周期浏览器和便携验证。真实用户库不用于试验，不自动删除任何现有记录。

偏好学习继续后置。本轮优先交付用户指出的真实使用障碍。

## 实施记录

已完成后端清理服务、来源最小保留、任务取消标记、公有API隐藏、逐项人工核对续接、三种处理出口与删除UI。后端173基础回归后增加跨简历隔离用例，共174项通过。TypeScript、Vite、Ruff与源码三套浏览器流程通过。独立后端审阅的junction越界和整支审阅的删除交互竞态均先复现失败再修复，保留回归用例。没有在用户真实资料上执行删除。保留当前功能分支，不推送。

最终结果：174项后端全部通过；Ruff、TypeScript、Vite通过；源码新生命周期、原M1与主管回归通过；便携包新生命周期和原M1完整回归通过，JS错误0。删除已采用任务后仍可通过简历入口读取原文、人工接管并重新审阅；候选/日志和重复身份信息会清除。
