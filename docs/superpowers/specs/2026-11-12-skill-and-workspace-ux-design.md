# Skill 与工作台主流程优化设计

## 意图

让用户在第一次使用时先明确求职方向，再放入材料并生成；同时把 11.8 Skill 中“按岗位选择价值重心、逐条来源映射、生成与审计分离”的优点吸收到现有分阶段工作流中，而不引入无证据的 Owner、0→1 或大 Scope 表述。

## 目标与非目标

- 目标：五个已有专项方向都可被新任务显式选择；未知方向明确回退通用规则。
- 目标：Skill 在 plan/draft/review/revise 四阶段都保留来源、角色、范围、结果口径边界，review 把角色、范围、结果、因果拆开审阅。
- 目标：首屏形成“选方向 → 放材料 → 确认发送 → 生成”的单一路径，助手默认折叠但仍可补充材料和局部修改。
- 目标：方向选择、材料状态、隐私确认与主动作在首屏可见，移动端仍可使用。
- 非目标：复制 11.8 的模板、视觉资产、发布配文或联网学校标签核验；改变现有五块简历骨架；增加新的模型调用；宣称真实模型质量提升。
- 反目标：不能为了更强表达把参与升级为 Owner，把原型升级为上线，把团队结果升级为个人结果。

## 约束

- 沿用 React 19、TypeScript、Vite、FastAPI、Pydantic 与现有 SQLite/执行图。
- 不增加运行依赖，不改变旧任务已冻结的 `pinned_role`。
- 新任务方向只来自显式 UI/对话选择；表单不从岗位名称猜测方向。
- 姓名与联系方式继续留在本机字段；材料发送仍需显式勾选确认。
- 当前环境的 WMI 与 `_ssl` 故障必须与产品测试结果分开报告。

## 方案比较

1. **只改 Skill 文本。** 改动最小，但算法、数据、运营仍无法从新建表单进入专项规则，界面问题不变。
2. **重做整套三栏工作台。** 视觉变化大，但会同时触碰历史、编辑、导出、人工核对和任务生命周期，风险超出本轮目标。
3. **打通方向路由并重排首屏主流程（采用）。** 保留现有编辑与交付闭环，只改新建入口、助手默认状态和 Skill 阶段资源；能直接消除静默通用回退和重复入口的主要摩擦。

## 设计

### 方向路由

定义共享的前端方向选项：产品、后端、算法/Agent、数据分析、内容/用户运营、其他。UI 初始不预选，用户必须显式选择；“其他”明确说明使用通用规则。后端 `GenerationInput` 接受同一集合，`load_skill` 映射到已有五个角色文件或 general。旧任务用 `pinned_role` 保持原快照。

### Skill 吸收

- 在入口中加入“先确定读者要据此判断什么能力”，避免工具清单式改写。
- 在契约中要求 plan 形成 `目标关注点 → fact_id → 本人动作 → 交付/验证 → 未知项` 的内部映射，draft 每条与经历元数据继续引用 fact_ids。
- review/revise 新增原子主张审阅参考：分别检查身份/角色、责任范围、交付状态、数字口径和因果归因；缺少公开证据不等于用户陈述为假，只有输入内直接冲突或越界才阻断。
- 保留现有程序校验与独立质量四维，不新增模型请求。

### 首屏交互

- 欢迎区改成明确的四步进度，不再把方向藏在“选填”。
- 方向选择置于材料上传之前，使用可点击卡片并说明专项规则/通用回退。
- 目标岗位与方向同区展示；材料上传、识别结果、发送确认和生成按钮按顺序排列。
- 已识别材料显示简短状态，生成按钮文案随前置条件变化。
- 姓名、联系方式、教育、求职背景、原文编辑、JD 文本和高级选项保留在“补充与高级选项”。
- 右侧助手首次默认折叠；用户主动展开后仍可上传、聊天、回答追问和发起局部修改。

## 验收

- 六种方向输入都能通过 API，五个专项方向分别加载对应角色资源，其他加载 general；旧任务 pin 不变。
- 新建首屏未选方向时不能生成；选择算法、数据或运营时不再落到 general。
- 首屏只出现一条主要材料生成路径，助手默认折叠，展开后功能仍在。
- TypeScript、Vite、定向后端测试通过；完整测试若受 WMI/_ssl 阻断，必须给出可复现证据并尽量使用兼容启动方式复验。
- 浏览器检查桌面与窄屏首屏，无横向溢出、主按钮与方向可见、控制台无新增错误。
