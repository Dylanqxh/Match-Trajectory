# Resume Skill 与 Responses 中转站迭代设计

## 目标

本轮解决两个相互独立、但会在真实简历生成链路汇合的问题：

1. 吸收外部 `resume-skill` 中可泛化的写作判断方法，增强现有运行时 Skill，而不替换本项目既有的事实校验、任务快照、角色路由和结构化草稿协议。
2. 让用户配置的第三方中转站可显式选择 OpenAI Chat Completions 或 OpenAI Responses 协议，使连接测试、生成、智能编辑与工具能力测试共用同一协议边界。

## 已验证事实

- 外部 Skill 的优势集中在“读者要判断什么”“背景、结果与个人贡献如何分工”“指标是否真正解释价值”“方案之间是依赖、并行还是补充”等写作判断，而不是新的简历数据结构。
- 当前项目只有自定义 Chat Completions 适配；Anthropic 使用单独的 Messages 适配。
- 用户提供的中转站在同一组 Base URL、模型与 Key 下：模型列表成功，Chat Completions 失败，Responses 成功并返回指定文本。因此连接失败是协议不匹配，不是 Key 或模型不可用。

上述中转站 Key 只用于本机合成文本验证，不写入源码、文档、测试、命令行参数、日志或项目数据目录。

## Skill 融合设计

### 选择

新增一份所有生成阶段都加载的“贡献表达架构”资源，并对产品、运营角色规则和编辑规则做少量定向补充。运行时仍由 `app/skill.py` 把资源实际装入 `stage_instructions`；仅把文件放进 Skill 目录不算集成完成。

### 新增判断

- 先确定目标读者需要据此判断的能力，再决定经历的组织方式。
- 一段经历按业务目标与可独立验证的结果划界，不按工具清单或时间流水账机械拆分。
- 背景只解释问题和约束，结果说明发生了什么，贡献说明本人做了什么；三者不能互相冒充。
- 只有材料支持时才能描述方案之间的依赖、并行或补充关系，不得自行拼接因果链。
- 保留原始材料中有辨识度的领域术语；删除重复动作、过程噪声和无法解释价值的数字。
- 指标按解释力选择，并保留归属、分母、基线、时间窗与范围；活动次数不自动等于增长或业务结果。
- 加粗等强调应覆盖完整语义短语，优先“指标名称 + 变化”，而不是孤立数字或符号。
- 终检从招聘读者视角检查：能否看出问题、贡献、证据、边界以及目标岗位相关性。

### 保留边界

- 不复制外部 Skill 的输出 Schema、渲染格式或目录结构。
- 不降低数字、技术、时间、上线状态、熟练度和责任归属的现有事实门禁。
- 不从 JD 推断候选人拥有某项技能或结果。
- 不把外部示例当作用户事实，不加入针对单个样例的补丁规则。

## Responses 协议设计

### 配置模型

`ProviderConfig` 增加 `protocol`：

- `chat_completions`：默认值，保持现有 OpenAI 兼容中转站行为。
- `responses`：仅供 `custom` 供应商显式选择。

官方预设继续由项目决定协议，避免用户把 OpenAI、Anthropic、DeepSeek 或百炼预设误切到不匹配接口。记住配置时只把 protocol 元数据写入 `model-remember.json`；Key 仍只进系统钥匙串或服务内存。

### 请求适配

应用内部继续使用现有 Chat Completions 形状，协议边界负责转换：

- `messages` 转为 Responses `input` 消息；字符串内容转为 `input_text` 内容块。
- `max_tokens` 转为 `max_output_tokens`。
- 移除 Chat 专属字段，并设置 `store: false`。
- 函数工具从嵌套 `function` 转为 Responses 的扁平函数工具；强制工具选择同步转换。
- JSON 输出仍由现有提示词与解析校验兜底，不依赖某一家中转站是否完整实现结构化输出扩展。

### 响应适配

- 从 `output[].content[].output_text` 汇总文本。
- 从 `output[]` 的 `function_call` 恢复现有 `tool_calls` 形状。
- 把 completed/incomplete、max output token 等状态归一为现有 finish reason。
- 把 Responses usage 归一为 prompt/completion/total tokens。

连接测试、正式生成、Agent 编辑和工具探针必须都走同一套适配器，禁止只让“测试连接”成功而正式调用仍失败。

## 界面与诊断脚本

- 自定义中转站展示“接口协议”选择：Chat Completions / Responses。
- 已连接配置会恢复并显示 protocol；切换供应商时恢复安全默认值。
- `tools/test_model_connection.py` 增加 `--protocol`，Key 仍通过隐藏输入读取，结果不回显 Key。
- 不做自动“双协议重试”：它可能造成重复计费、把凭据发送到意外端点，并掩盖供应商真实协议。用户显式选择更可审计。

## 验证边界

自动测试覆盖端点、请求、文本响应、工具调用、配置验证、钥匙串元数据、API 与界面。真实中转站只发送合成短文本和最小结构化任务；成功证明当前凭据与协议可调用，不等于已证明所有长简历质量、稳定性、额度或供应商长期可用性。
