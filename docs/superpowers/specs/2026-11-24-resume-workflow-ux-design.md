# 简历生成工作流 UX 迭代设计

## 意图

把当前拥挤在同一画布中的材料采集、生成进度和简历编辑拆成三个明确阶段，让没有旧简历的人也能通过结构化表单提供材料，并让生成后的 A4 预览成为工作台主视觉。

## 目标

- 新建简历时同时提供“上传/粘贴已有材料”和“从空白表单填写”两条同级路径。
- 两条路径可以来回切换、内容不丢失，也可以合并为同一次生成的材料。
- 点击生成后进入独立执行页；该页承载阶段状态、补问、失败恢复和候选结果，不再嵌在材料表单中。
- 执行阶段使用清晰图标、阶段卡片和状态文案展示真实工作流，不伪造百分比。
- 生成完成后进入文档工作台；预览占主要宽度，并可切换“并排 / 专注预览 / 专注编辑”。

## 非目标

- 不改动生成 API 的阶段、预算、事实门禁和模型协议。
- 不新增图片、视频或音频能力。
- 不重做简历模板、PDF/DOCX 渲染或 Agent 对话协议。
- 不引入新的前端状态管理或 UI 组件依赖。

## 约束

- 保持 React 19、TypeScript、现有原生 CSS 和 FastAPI 接口。
- Node 版本要求保持 `>=22.12.0 <23`。
- 姓名和联系方式继续由本地字段维护；生成材料仍需显式确认发送范围。
- 手工结构化材料进入生成前必须转换为可引用的 `source_text`，长度不得超过 20,000 字。
- 旧材料、手工表单和可选 JD 的输入在页面切换后均不得丢失。
- 生成流程不显示虚假的确定性进度或费用金额。

## 方案比较

### 方案 A：在现有长表单中增加更多折叠项

改动最小，但继续把入口、执行和结果挤在一起，也无法解决预览过小。放弃。

### 方案 B：引入完整路由库与多页应用

URL 语义清楚，但现有应用没有路由层，生成任务和未保存表单状态会增加持久化与恢复复杂度。当前规模下收益不足。放弃。

### 方案 C：单页内部显式工作区状态（采用）

由当前 `record`、`jobId` 和任务类型推导 intake / generation / document 三个工作区；新组件只承载材料入口、执行展示和视图切换。复用现有 API 与状态，改动集中、可回退，也能完整解决三项反馈。

## 交互设计

### 1. 材料工作区

顶部保留方向选择和本地身份字段。材料区域显示两个同级入口卡：

- “上传已有简历”：上传 PDF/Word/TXT/Markdown，或粘贴已有材料；JD 保持独立且可选。
- “从空白表单填写”：使用现有分区编辑器填写基本信息、教育、工作/实习、项目和技能。

入口切换只改变当前可见编辑面板，不清空另一入口。生成时把上传/粘贴文本与结构化表单内容合并；相同内容不做模型推断式去重，只使用明确分段，避免误删事实。

### 2. 生成工作区

提交成功后只显示本次任务的独立工作区：标题、返回材料、任务状态、阶段轨迹、补问/失败恢复/候选草稿。侧栏任务仍可恢复该页面。

主阶段采用带图标的卡片序列：材料分析、简历写作、事实审阅、完成；补问、修正和可选主管作为分支说明。卡片状态来自真实回执，保留允许关系与恢复语义。

### 3. 文档工作区

并排模式把 A4 预览列扩大到画布主要宽度，编辑器作为辅助列。顶部增加三个可访问的视图按钮：并排、专注预览、专注编辑。专注预览时隐藏编辑列并将 A4 居中放大；专注编辑时隐藏预览列。窄屏保持单列，不制造横向滚动。

## 数据流

`buildGenerationSource(uploadedText, content)` 负责把两种材料合并为生成输入：

1. 保留上传/粘贴原文；
2. 将结构化教育、简介和各经历条目序列化为稳定的纯文本分段；
3. 跳过空字段和空条目；
4. 返回完整文本和字符数，由提交层执行 20,000 字上限提示；
5. 原始结构化 `education` 仍按现有字段单独发送。

工作区由纯函数推导，避免再增加一套会与 `jobId` / `record` 漂移的页面状态。

## 错误与恢复

- 材料合并后超过 20,000 字时不创建任务，保留全部输入并提示用户精简。
- 模型未连接、未选择方向或未同意发送时仍停留在材料工作区。
- 任务失败、等待补问或取消时仍停留在生成工作区；用户可返回材料区，内容不清空。
- 生成任务完成并自动采用后进入文档工作区，保留侧栏任务与版本记录。

## 验收

- 空白新建页能明确看到两条材料路径，切换后内容保持。
- 仅填写结构化教育或经历也能形成非空生成材料。
- 上传材料与表单经历同时存在时，生成请求包含两者。
- 点击生成成功后材料表单不再与进度组件同屏。
- 执行页显示真实阶段图标和状态，不显示百分比。
- 桌面宽屏下预览列大于编辑列，并能切换三种文档视图。
- 现有前端测试、TypeScript 检查和构建通过；Python 基线若仍受既有 Windows 环境故障影响，必须如实记录。
