# 选材、压缩与版面表达

## 先确定读者应记住什么

选材与起草之前，确定本次目标的2—3项核心能力；各找一条有本人动作或交付的证据。没有证据就标为缺口，不靠关键词补齐。
选择最能证明这些能力的经历，避免按材料出现顺序逐句改写。一个经历只保留不同的贡献，摘要、项目、技能不要反复介绍同一件事。

## 信息结构

- 姓名、联系方式、目标由宿主填写，不放入生成正文。
- fixed_education 非空时，教育由宿主原样回填；不要改名、改专业、改学历，不在其他板块重复教育。
- 没有固定教育时，education 只能从原文抽取；仅说“双一流高校”不能编出校名，school 留空。学历、专业按已知信息写，缺日期留空。
- 每个项目／任职／科研课题各为一个 section：title 写具体名称；kind 区分 project/work/research/skills/other；organization 与 role 只写已有依据的组织和责任。
- 项目名称未提供时可用任务用途做中性标题，例如“结构化信息抽取实验”；不能命名成原文不存在的商业产品。
- 起止日期仅取自对应经历的原文，格式 YYYY 或 YYYY-MM，仍在进行且有依据时 end_date=至今。不能用“前段时间”、学历或相邻项目反推时间。
- 同类经历倒序，未知时间放后且保留原顺序；经历内的条目按证据价值排序，不用日期排句子。
- 每个 section 的 fact_ids 支撑标题、组织、角色与日期；education 的 fact_ids 支撑对应学校与时间；正文每条仍各自引用。

## 起草预算：优先一页可扫读

- 简介可不写；需要时1—2句、通常50—90字，只写与目标相关的身份和已有实践，不写求职意愿、学习热情或长篇研究兴趣。
- 每段核心经历通常2—4条；材料少时1条也可以，不为达到数量凑内容。每条优先40—90字，原则上不超过110字。
- 每条集中表达一项贡献：**本人动作＋关键方法／判断＋可核对的交付／验证**，要素依证据取舍，不强凑句式。
- 背景压为一句或并入首条；避免“从需求梳理到实现基本自己推进”后又逐阶段重复，改写为具体已完成的动作与成果。
- 技能通常2—3条短句，按能力组合，写清“熟悉／使用过／接触过”；不把持续看论文写成研究成果，不重复整段项目。
- 用户说“提升明显”“有一定下降”但未给数值时，优先写评估口径、基线、记录和已交付脚本；必要时保留限定的定性结论，不写成确定的量化突破。
- 交付形式、评测对照、可复现材料和实际使用范围往往比平台清单更重要。平台和工具只有支撑方法时才写，不单独凑卖点。

## 有节制地突出重点

正文 items.highlights 可选，每条最多2个原文短语，每处不超过30字；通常选一个关键方案或交付，不能整句加粗。
短语必须逐字出现在该条 text 中，不输出 Markdown 的 ** 或 HTML；宿主统一渲染。少量强调，不能所有技术名都加粗。
优先突出能展开的证据，如“基线对照评测”“可复现评估脚本”，而非“优秀”“自主设计”等评价。

## 审阅与修正

先查事实，再查是否体现目标能力、本人贡献和交付；最后查长度、重复、空话及重点。引用存在不等于表达有证据。
质量问题用 warning：指出具体条目以及删什么、保留什么。缺时间、缺数字、段落长本身不是事实错误，不得据此 blocking。
根据 issues_to_fix 压缩时，不删除否定和责任边界，不补新技术、日期或成果，不移动未受影响的经历；保留稳定 ID 和引用。
不要因为压短后信息少就重新扩写。达到预算仍有建议时交付带提醒草稿，不能无限修正。
