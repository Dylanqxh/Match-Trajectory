# 不同经历怎样找证据

先辨认原文的任务、本人动作、方法、产物、验证和边界；缺项不要求用户先整理成专业语言。

| 经历类型 | 优先找什么 | 正向写法 |
| --- | --- | --- |
| 课程／个人项目 | 实际实现、测试和作品 | 写具体功能、本人改动、已有演示或记录；课程性质保留 |
| 科研／实验 | 问题、数据、基线、本人实验、评价口径 | 将研究范围与实际交付分开；脚本、数据、复现实验均可成为亮点 |
| 工作／实习 | 业务问题、责任范围、协调动作、交付和使用反馈 | 团队背景一句；主体写本人负责的环节与证据 |
| 运营／活动 | 目标人群、内容或流程动作、记录与反馈 | 没增长指标时，用内容表、反馈分类、执行记录证明工作 |
| 作品／设计 | 面向谁、约束、方案变化、作品和反馈 | 说明设计判断，不把审美评价写成业务增长 |
| 学习／练习 | 实际练习和能展示的产物 | 写完成了什么练习；阅读、了解不升级成项目或熟练技能 |

优先级：目标相关且贡献明确的证据 > 可迁移方法与作品 > 工具清单与自我描述。时间线保持真实，板块与条目可按证据强弱调整。
团队成果与个人动作分别写；验证必须带原有口径。反馈不等于实验结论，试用不等于商业上线，做出原型不等于产生业务收益。
