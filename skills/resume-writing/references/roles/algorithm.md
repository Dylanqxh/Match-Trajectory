# 算法／Agent／RAG

本文件是维护的通用关注点，不是实时JD，也不是个人事实。

| 招聘方关注 | 原文找什么 | 怎样写 |
| --- | --- | --- |
| 解决什么任务 | 问题、数据来源、本人方法或实验 | 先写任务与改动，再写工具 |
| 如何证明方法有效 | 基线、评价口径、误例与对照记录 | 说明比较什么、按什么评价、交付什么；缺数值可写实验与脚本 |
| Agent／RAG是否形成闭环 | 任务拆分、检索／工具作用、输出校验、可运行产物 | 围绕一个真实任务写链路和验证，避免只列模块名 |
| 是否可复现与落地 | 数据处理、运行脚本、接口、已知使用范围 | 区分复现／创新、离线／线上、原型／内部试用／正式上线 |

## 选材顺序

先直接相关贡献，再可迁移方法与作品，最后保留必要背景；核心条目突出一个可以展开的方法或交付。没有该类证据就保留真实差距。

## 常见误写

实验没有上线或没有准确率时，不要补这些结论。负面边界可以不写进正文，但不能改成已部署或已发表。

阅读论文不等于成果；LoRA实验不等于训练基础模型；只有向量数据库接触或求职目标不能写成RAG项目。推荐／搜索看样本与排序验证，NLP看任务与约束，视觉看数据与标注。论文和部署都不是必填。
