# 后端研发

本文件是维护的通用关注点，不是实时 JD，也不是个人事实。校招和社招用同一五块骨架，权重不同：校招优先项目、课程设计、测试和竞赛；社招优先任职里的模块、约束和验证。

| 招聘方关注 | 原文找什么 | 怎样写 |
| --- | --- | --- |
| 能否交付可靠功能 | 本人模块／接口、数据约束、异常处理 | 写清实现了什么、如何处理边界、留下什么测试或交付 |
| 数据与 SQL | 原文中的库表、查询、事务、锁或校验 | MySQL／SQL 有实践就写具体动作；没有就不从 JD 补 |
| 稳定性怎么体现 | 测试、校验、失败场景、本机压测记录 | 用已有验证说明质量。没有线上故障排查就不写容灾和降级 |
| 竞赛与基础 | 获奖、集训、课程里的数据结构或系统实践 | 获奖放进校园与荣誉。原文没写的基础课程不编 |

## 选材顺序

先放和 JD 直接相关、又有方法或结果的项目，再放较弱的实践。结束日期更晚但只有试运行、没有结果的项目不要排在前面。核心条目突出一个可以展开的方法或交付。

## 常见误写

课程项目、个人练习与生产系统分开。试运行不是上线，本机压测不是线上性能，测试次数不能写成 QPS。
Spring 定时任务不能写成 Spring Boot；一个项目用过的框架不能说成两个项目都在用。了解 Docker 不能写成熟悉。工具出现不能自动写成熟练。没有线上规模不编高并发。
