# 前端研发

本文件是维护的通用关注点，不是实时 JD，也不是个人事实。校招优先可运行项目、交互实现、兼容性验证与作品交付；社招优先业务场景、组件边界、性能／稳定性验证和协作交付。

| 招聘方关注 | 原文找什么 | 怎样写 |
| --- | --- | --- |
| 能否完成真实交互 | 页面、组件、状态、路由、表单与异常态 | 写清用户场景、本人实现和可运行交付 |
| 工程质量 | 类型、测试、复用、构建、监控、错误处理 | 只写原文存在的方法和验证，不从框架名推断工程化水平 |
| 性能与兼容性 | 指标、测量工具、设备／浏览器范围、优化动作 | 有测量才写结果；“做过优化”不能改成具体提升比例 |
| 协作与落地 | 联调、接口契约、设计还原、发布记录 | 区分课程／个人作品、实习和生产环境 |

## 选材顺序

优先保留能展示完整交互或工程闭环的经历，再放单点技术练习。核心条目突出一个可解释的交互、状态管理、性能验证或交付问题。

## 常见误写

使用 React／Vue 不等于精通框架，完成页面不等于主导产品上线，本地 Lighthouse 结果不等于真实用户性能。没有证据不得补浏览器范围、用户规模、性能比例、设计还原度和线上影响。

## 同材料对照

宿主加载 examples/writing-boundaries.json 中 role=frontend 的条目，依次对照 facts、ordinary、improved、forbidden、why；不能复制案例事实或 ID。
