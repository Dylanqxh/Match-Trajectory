# 写法来源

下面只记录借鉴了哪些公开原则。没有整份抄写对方 Skill，也没有把对方示例里的公司、数字或英文套话拿来当用户事实。

- [Paramchoudhary/ResumeSkills](https://github.com/Paramchoudhary/ResumeSkills)（MIT）：仓库说明强调用材料优化简历，而不是另编经历。本次只读了仓库说明和许可证，没有逐份读取其中的 Skill 正文。
- [varunr89/resume-tailoring-skill](https://github.com/varunr89/resume-tailoring-skill) 的 `branching-questions.md` 与 `matching-strategies.md`：追问应随已有回答分支，问过的细节不要再问，用户说没有就停止。本项目把它收成一轮、最多 3 个选择题；不采用多轮开放追问，也不向用户索要材料里不存在的指标。
- [resumx/skills](https://github.com/resumx/skills) 的简历写作说明：动作开头、关键词放在真实任务里、XYZ 只在结果确实存在时使用、空泛套话会伤害可读性。不采用其英文动词表，也不把第三方统计数字写进中文简历。
- [dabydat/resume-builder-skill](https://github.com/dabydat/resume-builder-skill)（MIT）：先让读者扫到任务和结果，STAR/XYZ 只作结构提醒。不采用其版式、字体和英文示例。

本地参考 `resume-skill` 里，目前只采用了已经读到的技术改写原则：先还原任务、约束、本人改动、技术关系和验证范围；结果要早到能扫读；同一目标的业务流可以放在一段实习里，但不能把相邻动作写成数据流或因果；只有真实反馈关系才叫闭环；机制、边界、规模和验证范围要留下来；系统收益不能挪到组件上；论文身份和团队名次可以写，但不能夸大个人作者位次或排名。`rewrite-rules.md`、`product-rewrite-rules.md`、`operations-rewrite-rules.md`、`highlight-rules.md`、`style-guide.md` 这次没有读到，不能把它们算作已经核对过的本地规则。
