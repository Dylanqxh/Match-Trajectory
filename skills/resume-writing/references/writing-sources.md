# 写法来源

下面只记录借鉴了哪些公开原则。没有整份抄写对方 Skill，也没有把对方示例里的公司、数字或英文套话拿来当用户事实。

- [Paramchoudhary/ResumeSkills](https://github.com/Paramchoudhary/ResumeSkills)（MIT）：仓库说明强调用材料优化简历，而不是另编经历。本次只读了仓库说明和许可证，没有逐份读取其中的 Skill 正文。
- [varunr89/resume-tailoring-skill](https://github.com/varunr89/resume-tailoring-skill) 的 `branching-questions.md` 与 `matching-strategies.md`：追问应随已有回答分支，问过的细节不要再问，用户说没有就停止。本项目把它收成一轮、最多 3 个选择题；不采用多轮开放追问，也不向用户索要材料里不存在的指标。
- [resumx/skills](https://github.com/resumx/skills) 的简历写作说明：动作开头、关键词放在真实任务里、XYZ 只在结果确实存在时使用、空泛套话会伤害可读性。不采用其英文动词表，也不把第三方统计数字写进中文简历。
- [dabydat/resume-builder-skill](https://github.com/dabydat/resume-builder-skill)（MIT）：先让读者扫到任务和结果，STAR/XYZ 只作结构提醒。不采用其版式、字体和英文示例。

本地 `resume-skill` 的五份参考已通读。下面是吸收进本项目 Skill 的原则，以及因证据或隐私约束而没有照搬的部分。示例里的澄湾、北屿和数字只属于写法说明，不是用户事实。

### rewrite-rules.md

吸收：先决定读者要判断的能力，再按业务目标选材；背景、结果、职责分工，但不要求每段填满同一组标签；依赖、并行和补充必须有原文关系；保留能说明机制的术语，压缩时先删修饰和重复；代表性且口径清楚的结果要留下，组件收益不能升成系统收益；参与、负责、独立负责保持原强度。

不吸收：把「负责业务 / 业务效果 / 工作职责」写成所有经历的必填加粗标签。本项目已有标题、组织、岗位和日期字段，结果放在条目前半句即可。也不吸收「由起止点推算材料里没有的百分点差值」，因为新数字不算已有证据。

### product-rewrite-rules.md

吸收：一段经历证明一种产品能力，而不是每段都写调研、原型、上线；用户、场景、问题、范围先于功能名；取舍要写进了什么、明确不做什么；原型、测试和「反馈进入下一版」是三种不同证据；问卷数、页面数、版本数不是增长。

不吸收：把参考案例里的需求条数、情感支持场景或工具组合当成新材料的事实。技术经历不改成产品模板。

### operations-rewrite-rules.md

吸收：先定运营对象、目标行为和本人能改的动作；策略要写到机制和执行范围；活动场次、覆盖人数、合同额和收入彼此不能替代；整体结果与某一动作的局部结果分开，不能把同时出现的数字独占归因；只有记录了「调整之后又跟踪」才写反馈，不靠「闭环」二字。

不吸收：默认套上负责业务、运营成果、工作职责三套总标签。原岗位名称保持不变，不因写过 PRD 或 SQL 就改成产品或技术履历。

### highlight-rules.md

吸收：加粗应是能单独看懂的动作、对象、机制或「指标名加变化」，而且必须是正文里的连续原文。

不吸收：取消每条两处、每处 30 字的上限，或让产品和运营自动加粗更多处。空的 highlights 目前仍会由宿主补扫描锚点，这一行为没有改。

### style-guide.md

吸收：事实和角色边界不因文风改变；联系方式和内部数据是否公开，以用户已经确认的字段为准。

不吸收：为了增强学校标签去查官网、主管部门或高校联盟。材料或教育字段里没有的 985、211、双一流不能补。政治面貌也不从正文自动提取，只保留用户写进档案补充的内容。
